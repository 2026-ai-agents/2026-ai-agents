## Part 4. v0.2 · 서랍

부탁한 기억이 thread를 넘는다.

</Slide>

<Slide>

### 무엇이 바뀌나: store가 checkpointer 옆에

```python
# 두 기억이 같은 pg를 나눠 쓴다: thread별 열쇠(checkpointer)와 사용자별 서랍(store)
pool = ConnectionPool(DATABASE_URL, kwargs={"autocommit": True})
checkpointer = PostgresSaver(pool)
checkpointer.setup()
store = PostgresStore(pool)
store.setup()

graph = builder.compile(checkpointer=checkpointer, store=store)
```

같은 pool 위에 **각자 자기 테이블**을 만듭니다.

</Slide>

<Slide>

### 코드 발췌: 서랍을 여는 곳

```python
def advisor(state: SecretaryState, config, *, store: BaseStore) -> dict:
    """store는 compile(store=…)로 주입된다 — 서랍을 열어 프롬프트에 싣는 지점."""
    memories = list_memories(store, state["user_id"])
    system = SYSTEM_PROMPT.format(..., memories=render_memories(memories))
```

읽기는 advisor가 합니다.  
`compile(store=…)`로 주입된 store를 노드가 **시그니처로 받는 것**이
LangGraph의 공식 규약입니다.

</Slide>

<Slide>

### 코드 발췌: 서랍에 넣는 곳

```python
def ns(user_id: int) -> tuple[str, str]:
    """사용자별 서랍 주소. 격리는 네임스페이스가 책임진다."""
    return ("memories", str(user_id))

def save_memory(store: BaseStore, user_id: int, fact: str) -> str:
    key = uuid.uuid4().hex[:8]
    store.put(ns(user_id), key, {"fact": fact})
    return key
```

쓰기는 `remember` 도구가 합니다.  
네임스페이스 `("memories", user_id)`가 사용자별 격리를 책임집니다.  
**남의 서랍은 열리지 않고, 테스트가 그것을 박제합니다.**

</Slide>

<Slide>

### store가 주는 것은 셋

- `put(ns, key, value)`: 서랍에 넣는다.
- `get(ns, key)` · `list`: 꺼내 본다.
- `search(ns, query=…)`: **의미로** 찾는다 (v1.0에서 씁니다)

네임스페이스 `ns`가 서랍의 주소이고,
여기서는 `("memories", user_id)`입니다.

</Slide>

<Slide>

### 기억은 프롬프트에 이렇게 실립니다

- advisor가 매 턴 서랍을 열어 **시스템 프롬프트에 렌더**합니다.
- 도구도 아니고 검색도 아닙니다. 그냥 **읽고 시작하는 쪽지**입니다.
- Day 1 2세션에서 본 "대화를 새로 열어도 남는 기억"의 구조 그대로입니다.

</Slide>

### 결과 읽기: 저장된 곳이 운명을 갈랐다

- 같은 대화에 있던 두 사실의 운명이 갈렸습니다.
- 부탁한 디카페인은 **store에 들어 새 thread에서 살아남았고**,
- 흘린 테니스는 **checkpoint에만 남아 thread와 함께 갇혔습니다**.

## Part 5. v0.3 · 판단

부탁하지 않아도 담을 것을 담는다.

</Slide>

<Slide>

### v0.2의 한계

- 사용자가 **명시적으로 부탁해야만** 담깁니다.
- 흘리듯 말한 사실은 그대로 흘러갑니다.
- 그런데 사람이 비서에게 "이거 기억해 줘"를 매번 말하지는 않습니다.

</Slide>

<Slide>

### 진짜 비서는 "기억해 줘"를 기다리지 않습니다

- 답이 나온 뒤, **턴이 끝나기 전에** memorize 노드가 이번 턴의 대화를 읽습니다.
- 오래 기억할 가치가 있는 사실만 골라 서랍에 넣습니다.

</Slide>

<Slide>

### 턴이 끝나기 전, 판단이 한 번 더

```mermaid
sequenceDiagram
    participant U as 사용자
    participant A as advisor
    participant M as memorize
    participant S as store
    U->>A: "다음 달에 성수동으로 이사 가요"
    A-->>U: 답변 (이사 준비 도와드릴게요)
    Note over M: 턴이 끝나기 전, 판단이 한 번 더
    M->>S: 이미 아는 것 조회 (중복 방지)
    M->>M: 기억할 가치가 있는가?
    M->>S: put("다음 달 성수동으로 이사한다")
```

</Slide>

<Slide>

### 코드 발췌: 판단 기준은 프롬프트에 산다

```python
MEMORIZE_PROMPT = """당신은 개인 비서의 기억 판단기다. …
## 판단 기준
- 사용자에 대해 **오래 기억할 가치가 있는 사실**만 고른다: 취향, 건강·알레르기,
  가족·거처, 반복되는 습관, 앞으로의 대화에 계속 쓰일 사정.
- 잡담, 일회성 요청, 그때뿐인 감상은 버린다.
```

### 임베딩까지 대역으로

- LLM은 각본 대역, db는 진짜라는 규약에 이음새가 하나 더해집니다.
- **임베딩도 대역**입니다.
  conftest가 임베딩 함수를 텍스트 해시 기반의 결정적 벡터로 갈아 끼웁니다.
- 키 없이도 인덱싱·limit·격리 같은 **기계 동작**을 검증합니다.
- 의미 순위의 품질은 대역으로 잴 수 없으므로 실제 임베딩의 몫으로 남기고,
  데모에서 실측합니다.

```python
def test_memorize_replaces_stale_fact(monkeypatch):
```

### 세 가지 기억, 다시 정리

| | 어디에 | 언제까지 | 누가 쓰나 |
| --- | --- | --- | --- |
| 일정 | `events` 행 | 지울 때까지 | 도구가 SQL로 |
| 대화 | checkpoint | 그 thread 안 | 그래프가 자동으로 |
| 사실 | store | 사용자가 지울 때까지 | advisor가 매 턴 |

사이드바의 🗑 버튼은 장식이 아닙니다.

## 이 세션이 남기는 것

- 기억에는 수명이 있다.
  도메인 행(영구), checkpoint(thread 안), store(사용자에 붙음)는
  같은 db의 다른 테이블이다.
- store는 네임스페이스로 격리되는 사용자별 서랍이고,
  노드는 `compile(store=…)` 주입으로 연다.
- 무엇을 기억할지는 코드가 아니라 프롬프트의 판단 기준이 정한다.
  판단이 죽어도 답변은 살아야 한다.
- 기억이 쌓이면 전부가 아니라 의미가 가까운 것만 싣는다.
- 사실은 변한다. 서랍은 remove로 갈아 끼우는 살아 있는 기억이다.
