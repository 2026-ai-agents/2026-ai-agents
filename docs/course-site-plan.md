# 강의 문서 세션 분할 계획

`docs/course-plan.md`의 절 하나를 강의 문서 하나로 옮겨, 일차 단위가 아니라
**세션 단위 URL**을 갖게 하는 작업의 계획서다. 실행 전 합의용 문서이며,
작업이 끝나면 결과를 `site/README.md`와 `CHANGELOG.md`에 반영한다.

## 왜 바꾸는가

지금은 일차 하나가 문서 하나다.

```plaintext
/course/day-01/      Day 1 전체 (240분, 8개 블록)
```

세션마다 다루는 저장소·릴리즈·예제가 다르므로 한 문서에 다 넣으면 길어지고,
수업 중 "지금 보는 자료" 링크를 세션 단위로 줄 수 없다. 바꾼 뒤에는 이렇게 된다.

```plaintext
/course/day-01/                  Day 1 개요 (로드맵·릴리즈 사다리·세션 목록)
/course/day-01-session-01/       오리엔테이션과 환경 점검 (15분)
/course/day-01-session-04/       Tool calling 심화 (40분) → v0.2
```

## 슬러그 규칙

- 파일: `site/src/content/courses/ko/day-<NN>-session-<NN>.mdx`
- URL: `/course/day-<NN>-session-<NN>/`
- 개요 문서는 기존대로 `day-<NN>.mdx` → `/course/day-<NN>/`
- 두 자리 zero-padding을 지킨다. `day-1-session-1` 같은 변형을 만들지 않는다.

## 세션 목록

설계 원칙, 마무리)도 실제 강의 시간을 차지하므로 세션 번호를 받는다. 원안의

## 프론트매터 규약

```yaml
---
title: "Day 1 · 4. Tool calling 심화"
description: "도구 스키마와 tool call 왕복을 예제 10종으로 해부하고, v0.2에서 예산 계산 도구가 실리는 지점까지"
summary: "…"
date: 2026-08-14
category: day-1
hours: "40분"
order: "3896"
level: 1
slides: ["day-01-session-04"]
tags: ["tool calling", "Pydantic", "v0.2"]
---
```

### order는 내림차순이다 (중요)

테마의 `getCourses()`는 `order`를 **내림차순**으로 정렬한다. 구현은
`stack-site-builder/src/lib/courses.ts`에 있고, 큰 값이 먼저 나온다. 그래서
시간 순서대로 보이게 하려면 뒤 세션일수록 작은 값을 줘야 한다.

```plaintext
order = (4 - 일차) * 1000 + (900 - 세션번호)      # 개요는 세션번호 0
```

| 문서 | order |
| --- | --- |
| `day-01` (개요) | `"3900"` |
| `day-01-session-01` … `-08` | `"3899"` … `"3892"` |
| `day-02` (개요) | `"2900"` |
| `day-02-session-01` … `-05` | `"2899"` … `"2895"` |
| `day-03` (개요) | `"1900"` |
| `day-03-session-01` … `-06` | `"1899"` … `"1894"` |

- 실제 빌드로 확인한 동작이다. `3899` → `3898` → `3897` 순서로 표시된다.
- **기존 `day-01`/`day-02`/`day-03`의 `order`가 `"01"`/`"02"`/`"03"`으로
  들어가 있는데 방향이 반대다.** 지금은 `/course/`가 카테고리로 먼저 묶여서
  결과가 우연히 맞을 뿐이고, 한 카테고리에 문서가 둘 이상 생기는 순간 드러난다.
  이 작업에서 위 표대로 교체한다.

### hours를 쓴다

테마에 `hours` 필드가 있고 카드와 상세 페이지 양쪽에 그대로 표시된다.
세션 길이를 여기에 넣으면 본문에 시간을 중복해 적지 않아도 된다. 확인 완료.

## 개요 문서의 역할

개요 문서(`day-01` 등)는 세션 문서로 옮겨간 내용을 중복하지 않고, 일차 전체를
조망하는 것만 남긴다.

- 그날의 교재 저장소와 형태
- 릴리즈 사다리 표 (세션과의 대응)
- 세션 목록 표 (제목·시간·링크)
- 그날의 큰 그림 mermaid, 실패 재현 시나리오 요약

## 슬라이드

덱도 세션과 1:1로 간다. 폴더명을 강의 슬러그와 같게 두면 대응이 자명하다.

```plaintext
site/src/content/slides/ko/day-01-session-04/index.mdx
```

- 강의 문서의 `slides: ["day-01-session-04"]`로 연결한다
- 지금 있는 `slides/ko/day-01/`은 내용이 오리엔테이션(과정 규칙·저장소·릴리즈
  사다리·Day 1 흐름)이므로 **`day-01-session-01`로 옮긴다**
- 덱이 필요 없는 세션은 `slides: []`로 두고 나중에 채운다

## 작업 순서

`feature/base_setup`을 `develop`에 머지한 뒤, `feature/course-sessions`
브랜치에서 진행한다. 커밋은 단계별로 나눈다.

1. `order` 방향 수정 + `hours` 도입 (기존 3개 문서)
2. Day 1 세션 8개 생성, `day-01` 개요를 조망용으로 축소
3. Day 2 세션 5개 생성, `day-02` 개요 축소
4. Day 3 세션 6개 생성, `day-03` 개요 축소
5. 슬라이드 덱 이름 변경 (`day-01` → `day-01-session-01`)
6. `site/README.md`(콘텐츠 작성 위치·order 공식), `docs/documentation-rules.md`,
   `CHANGELOG.md` 갱신

각 단계 후 `cd site && pnpm build && pnpm check`와
`python3 scripts/check-style.py`를 돌린다.

## 선행 확인 사항

세션 문서를 쓰기 전에 원안에서 정리되어야 할 것들이다. `course-plan.md`는
외부 원본이라 이 저장소에서 고치지 않으므로, 원본 쪽에서 정리한 뒤 반영한다.
상세는 아래 "원안 점검 결과" 참고

- **휴식 시간**: 3일 모두 블록 합이 정확히 240분이라 쉬는 시간이 0분이다.
  세션 문서의 `hours`를 확정하려면 이 결정이 먼저 필요하다.
- **★ 예제 개수**: 원안은 "약 25종"이라는데 실제 별표는 20개다. 세션별 예제
  목록을 옮길 때 어느 쪽을 따를지 정해야 한다.
- **`core` 저장소**: 9개 저장소 중 유일하게 어느 세션에도 등장하지 않는다.
  어느 세션에서 소개할지 정해야 그 세션 문서에 넣을 수 있다.

## 원안 점검 결과

`docs/course-plan.md`를 훑어 확인한 사항이다. 원본을 고치지 않고 여기에만
기록한다.

### 확인된 문제

| # | 항목 | 내용 |
| --- | --- | --- |
| 1 | 휴식 시간 0분 | Day 1·2·3 모두 블록 합이 정확히 240분. 4시간 연속 진행이 되며, 한 세션만 밀려도 뒤가 전부 밀린다 |
| 2 | ★ 개수 불일치 | §8은 "★ 약 25종"이라 하는데 실제 별표는 20개 (01_api 4 · 02_litellm 3 · 03_tools 4 · 04_react 1 · 05_loops 3 · 06_harness 5) |

| 4 | 시간 중복 표기 | §7.1\~§7.4는 제목과 하위 불릿에 같은 시간을 두 번 적는다. 기계로 합계를 내면 205분이 이중 계산된다 |

| 7 | 단계 번호 혼선 | §6.4의 "5차 · app 리턴", "6차 · ui 표시"는 선별·검증 단계가 아닌데 같은 번호 체계를 쓴다 |

### 확인 필요

- **음식 DB 건수**: 원안은 "약 2만 건"이라 하는데, 출처로 지목한
  `week03-meal-planner`의 정제 데이터는 30만 건대다. 2만 건이 별도 스냅샷인지
  확인이 필요하다.
- **권장 RAM**: §10은 8GB 이상 권장이다. `food-rag-agent`는 컨테이너 4개
  (app·ui·db·rag), `coding-agent`는 산출물 스택이 따로 뜬다. 16GB 권장이 안전하다.

### 이상 없음

- 저장소 9개, Day 2 4개 · Day 3 3개, 제품형 에이전트 7종 집계가 §2.1·§8·§9에서 일치
- 릴리즈 단수 표기(5단·4단)가 실제 나열과 전부 일치
- 예제 51종이 6개 폴더 합계와 정확히 일치 (11+10+10+4+6+10)
- 실패 재현 시나리오 5종이 §2.2와 §8에서 일치
- MCP를 Day 1(가져오기)과 Day 3(내어주기)으로 나눈 구성이 일관됨
- 총 시간 720분이 240분 × 3일과 일치
