# 콘텐츠 작성 규칙

`site/` 아래 모든 콘텐츠(강의·글·개념·슬라이드·페이지)와 저장소 문서(README 등)에
적용하는 기본 규칙. 사람이 쓰든 AI가 쓰든 동일하게 따른다.

예외: [course-plan.md](course-plan.md)는 외부 원본을 그대로 옮긴 파일이라
이 규칙과 스타일 검사에서 제외한다.

## 한글 문장 스타일

- **닫는 괄호로 끝나는 문장에는 마침표를 겹치지 않는다.** `).` 형태를 만들지 않는다.
  - 좋음: `릴리즈 사다리로 진행 (v0.1에서 v1.0까지)`
  - 나쁨: `릴리즈 사다리로 진행 (v0.1에서 v1.0까지).`
- **문장 종결 마침표는 서술형에만 붙인다.** 문장이 서술어(`~합니다`, `~입니다`,
  `~한다`, `~하세요` 등)로 끝나면 마침표를 찍고, 명사·명사형(`~에이전트`, `~함`,
  `~없음`, `~정리`, `~까지` 등 체언 종결)으로 끝나면 마침표를 찍지 않는다.
  - 서술형: `저장소 하나가 완결된 에이전트 제품입니다.`
  - 명사형: `3일 12시간 과정` · `릴리즈 사다리` · `핵심 개념 정리`
  - 카드 설명·태그라인·불릿처럼 명사구로 끝나는 짧은 문구는 마침표 없이 쓴다.
    (기계로 판별하기 어려워 `check-style.py`가 잡지 못하므로 눈으로 지킨다.)
- **한글 문장에서 줄표(`—`)로 잇지 않는다.** 줄표(em dash, `—`)로 두 구절을
  잇거나 곁들이는 형태는 쓰지 않는다. 문장을 끊어 마침표로 맺거나, 리스트로
  나누거나, 쉼표·콜론·괄호로 바꾼다.
  - 나쁨: `모든 저장소는 compose 기반입니다 — 로컬 Python 환경은 필요 없습니다`
  - 좋음: `모든 저장소는 compose 기반입니다. 로컬 Python 환경은 필요 없습니다`
  - 코드 블록·mermaid 블록 안의 `—`는 예외
- **길게 늘여 쓰기보다 리스트로 나눈다.** 항목·이유·조건·단계가 여럿이면 한
  문장에 줄줄이 잇지 말고, 리스트로 분리해 한 항목에 한 가지만 담는다. 문단은
  짧게 두고, 나열형 내용은 리스트를 기본으로 삼는다.
- **긴 문단은 하드 브레이크로 문장을 나눈다.** 인트로 blockquote나 여러 문장이
  이어지는 긴 문단은, 한 덩어리로 렌더링되면 읽기 어렵다. 문장(또는 의미 단위)이
  끝나는 곳에서 줄 끝에 스페이스 2개를 넣어(하드 브레이크, 방법은 아래 마크다운
  규칙 참고) 렌더링에서도 줄이 나뉘게 한다. 소스는 기존처럼 어절 단위로 감싸되
  (중간 줄바꿈은 공백으로 이어짐), 하드 브레이크는 문장 끝에만 둔다.
  - 리스트로 이미 쪼갠 내용에는 쓰지 않는다. 대상은 문장이 이어지는 산문 문단이다

## 마크다운 규칙

- **소프트 줄바꿈(하드 브레이크)**: 같은 문단 안에서 줄을 바꾸고 싶으면
  줄 끝에 **스페이스 2개**를 붙이고 엔터. 스페이스 없이 엔터만 치면 렌더링될 때
  앞 줄에 그대로 이어진다. 빈 줄 하나는 문단 분리다.
- **표 안의 파이프는 이스케이프**: `|`는 표의 셀 구분자이므로, 셀 내용에
  파이프가 들어가면 `\|`로 쓴다. 위키링크도 마찬가지:
  - 표 안: `[[llm\|LLM]] API의 본질`
  - 표 밖: `[[llm|LLM]]` 그대로 사용 가능
- **물결표(~) 주의**: 한 문단에 `~`가 두 개 있으면 그 사이가 취소선으로
  렌더링된다. 범위 표기는 `v0.1\~v1.0`, `3\~4개`처럼 이스케이프한다.
  코드 블록과 mermaid 블록 안에서는 이스케이프하지 않는다.
- **볼드 경계와 문장부호+한글**: 닫는 `**` 바로 앞이 닫는 괄호·따옴표 같은
  문장부호이고 바로 뒤에 한글(조사 등)이 붙으면, CommonMark 규칙상 강조로
  인식되지 않아 `**`가 화면에 그대로 노출된다.
  - 나쁨: `**제어권 이양(handoff)**이고` (`)**이` 지점에서 깨짐)
  - 해결 1 (권장): 볼드 뒤에 조사가 바로 붙지 않게 문장을 다듬는다.
    `**제어권 이양(handoff)** 방식이고`
  - 해결 2: 괄호를 볼드 밖으로 뺀다. `**제어권 이양**(handoff)`
  - 해결 3: 문장을 못 바꾸면 `<strong>…(handoff)</strong>이고`처럼 HTML 태그를 쓴다
  - 참고: `**볼드**(괄호)`처럼 볼드가 한글·영문으로 끝나고 뒤에 괄호가 오는
    형태는 문제없다. 문제는 볼드 경계가 "문장부호와 한글 사이"에 끼는 경우다
- **위키링크는 등록된 용어만**: `[[용어]]`는 `site/src/data/glossary.mjs`에
  등록된 키만 쓸 수 있다. 미등록 용어는 빌드가 실패하는데, 이는 의도된
  동작이다. 새 용어는 먼저 glossary.mjs에 추가한 뒤 본문에서 참조한다.
- **사이트 내부 페이지 링크는 절대 경로로**: `[사전 준비](/article/prep-guide/)`
  처럼 base 없이 `/`로 시작하는 경로를 쓴다. GitHub Pages의 base
  접두(`/2026-ai-agents`)는 `site/astro.config.mjs`의 remarkBaseLinks가
  빌드 때 자동으로 붙인다. `../..` 상대 경로나 base를 직접 쓴 링크는
  만들지 않는다. 위키링크는 용어집 전용이므로 페이지 링크에
  쓰지 않는다.
- **MDX에서는 꺾쇠 자동 링크 금지**: `.mdx` 파일에서 `<https://…>` 형태는
  JSX 태그로 해석되어 빌드가 실패한다. `[텍스트](URL)` 링크나
  `` `http://localhost:8501` `` 코드 스팬을 쓴다. 일반 `.md` 문서(docs/,
  README)에서는 꺾쇠 자동 링크를 써도 된다.

## 이 과정 고유의 표기

- **저장소 이름**은 원문 그대로 코드 스팬에 넣는다: `` `day-01` ``,
  `` `food-rag-agent` ``. 한글로 옮기거나 대소문자를 바꾸지 않는다.
- **컨테이너 이름**(`lab`·`app`·`ui`·`db`·`rag`)도 코드 스팬으로 쓴다.
  저장소 사이에서 공유되는 자원이 아니라 이름 규약이라는 점을 흐리지 않는다.
- **릴리즈 태그**는 `v0.1`·`v1.0` 형태로 쓰고, 범위는 `v0.1\~v1.0`처럼
  물결표를 이스케이프한다.
- **일차 표기**는 `Day 1`·`Day 2`·`Day 3`으로 통일한다.

## 슬라이드 규칙

- **줄바꿈 위치를 눈으로 확인한다.** 테마가 한글을 어절 단위로만 줄바꿈하도록
  처리하므로(word-break: keep-all) 글자 단위로 깨지지는 않지만, 마지막 어절
  하나만 다음 줄로 넘어가는 등 어색한 자리에서 꺾일 수 있다. 덱을 작성·수정한
  뒤에는 반드시 브라우저에서 슬라이드를 넘겨보며 제목·부제·리스트의 줄바꿈을
  확인한다.
- **어색하면 끊는 위치를 직접 정한다.** 하드 브레이크(스페이스 2개 + 엔터)로
  의도한 자리에서 줄을 나누거나, 문구 자체를 짧게 다듬는다.
- 화면 크기에 따라 줄바꿈이 달라지므로, 창 폭을 좁혀가며 한 번 더 확인하면
  좋다.

## 커밋 전 검증

- 사이트 콘텐츠를 고쳤으면 `cd site && pnpm build && pnpm check`가 통과해야
  한다. 표가 깨졌는지, 취소선이 생겼는지는 빌드만으로 잡히지 않으므로
  해당 페이지를 열어 눈으로 확인한다.
- 이 문서의 기계 검사 가능한 규칙(`).` 마침표 겹침, 취소선 위험 물결표,
  MDX 꺾쇠 링크, 볼드 경계, 줄표)은 `python3 scripts/check-style.py`로 잡는다.
  md/mdx를 고쳤으면 커밋 전에 실행한다.
